# OpenWorkLang (`.work`)

A declarative **agent programming language**. A `.work` file states the **WHAT** of a piece of
agent work (goal, inputs, outputs, tools, invariants, workflow) and the **HOW** (which executor
tier runs each action — `code` / `rule` / `http` / `ml` / `slm` / `llm` / `human` — which
run-time `params` a front agent binds, and the `escalation` limits that keep an agent in the loop).

It compiles into a **Work IR** dictionary (`work.yaml`) and a **LinkML** schema. This package has
no runtime dependency; [OpenWorkCompiler](https://github.com/baryonlabs/workcompiler) consumes the
Work IR, emits executable builds (`handlers/`, `rules/`, `models/`, `prompts/`), benchmarks them and
runs them with a front agent. OpenWorkCompiler vendors this repository as a git submodule
(`vendor/openworklang`) and also *generates* `.work` files from compiled agent sessions.

```text
work customer_renewal {
  goal: "Prepare the annual renewal proposal for a customer"
  params:
    - customer_id                 # bound from the request at run time
  inputs:
    - crm_contracts
  outputs:
    - proposal
  invariants:
    - verify_current_contract
    - use_current_pricing_policy
  workflow:
    - lookup_contract
    - price_offer
    - draft_proposal
  executors: {
    lookup_contract: code,
    price_offer: rule,
    draft_proposal: llm
  }
  escalation: {
    draft_proposal: agent,        # synthesized content — regenerated by an agent when params change
    on_error: fallback_to_frontier_llm
  }
}
```

```bash
pip install -e .            # or use it in place: PYTHONPATH=. python3 -m openworklang …
python3 -m openworklang compile examples/quality_analysis.work --linkml quality_analysis.linkml.yaml
python3 -m pytest -q
```

```python
from openworklang import parse_openworklang, compile_ast_to_work_dict, compile_to_linkml_yaml
ast = parse_openworklang("examples/quality_analysis.work")
work = compile_ast_to_work_dict(ast)      # dict — the content of work.yaml
schema = compile_to_linkml_yaml(ast)      # str
```

Grammar and semantics: [SPEC.md](SPEC.md). Both the `work <name> { … }` DSL and an equivalent YAML
document (`work:`/`name:` at the top level) are accepted.
